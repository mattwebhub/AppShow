# Mac App Store readiness evaluation

Evaluated 2026-09-09 against the local `webcam-presentation-and-review` source and current Apple documentation. **Verdict: NOT READY.** No sandbox trial, distribution archive, App Store Connect inspection, TestFlight run or submission was performed. The vector tray change does not alter these findings.

This is the App Store gate for the [public-release checklist](PUBLIC-RELEASE-CHECKLIST.md). It extends the [source readiness review](../reviews/2026-09-09-app-store-readiness.md) into testable acceptance criteria. The review's historical Debug PID/signature and older packaged artifacts are not proof about a future store archive.

## Decision method

Every A1–A12 gate is required unless an explicit product decision makes part of it inapplicable. **Fail** means local evidence conflicts with a criterion. **Not tested** means sufficient evidence is missing. Neither permits release. **Pass** requires evidence from the exact candidate and owner/date. Do not average a score; any unresolved required gate keeps the verdict NOT READY. Product decisions must also update the store description and test matrix.

## Evidence to collect on the candidate

- Export the store archive's entitlements and nested signing inventory; compare with the declared feature matrix. A valid development signature or hardened runtime flag is not evidence of App Sandbox or store distribution eligibility.
- Record a sandbox runtime matrix: first launch, permissions denied/granted/revoked, each retained capture mode, projects/import/export/bookmarks, audio, captions/downloads, assistant if retained, shortcuts, and cold relaunch.
- Attach archive-validation output, privacy report, exact dependency/source inventory, App Store Connect build number and TestFlight results. Keep credentials and personal data out of the evidence bundle.
- Record each gate's final owner, date, candidate SHA, artifact/build identifier, result and evidence link; rerun after changes that invalidate it.

## Work order

1. Owner decides the first store edition's feature set and resolves store distribution rights. Preserve the fully open-source decision unless the owner explicitly changes it.
2. Engineering adds an isolated store configuration and proves capture/edit/export inside App Sandbox. ScreenCaptureKit itself is not a blanket reason to disable sandboxing; Apple's official sample uses it.
3. Implement container storage/bookmarks and compatible assistant/shortcut behavior; remove the store updater payload. Validate resource downloads and failure paths.
4. Complete privacy/metadata/versioning, produce the distribution archive, test through TestFlight, and evaluate every gate again before submission.

## Primary references checked on 2026-09-09

- [Privacy manifests](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files): app/SDK declarations; [App Store Connect privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/): disclosure workflow.
- [Submitting to the App Store](https://developer.apple.com/app-store/submitting/) and [uploading builds](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds/): current submission workflow and build identification.
