# ADR 0021: Update provider runtimes through their distribution channel

Status: accepted for local implementation, 2026-09-09.

The owner requires an update path for bundled or downloaded Claude Code and Codex CLIs. Provider releases evolve independently of AppShow, and interrupted staging must not corrupt a working runtime set.

The Store edition ships exact provider versions inside the signed app. Its Settings → Agents page displays the versions from the embedded receipt and opens the Mac App Store. Provider executables are replaced only by an AppShow Store update. Claude receives both `DISABLE_AUTOUPDATER=1` and `DISABLE_UPDATES=1`; the latter also disables manual self-update. There is no runtime downloader, external installation search or self-update button in this edition. Apple guideline 2.4.5(vii) requires Mac App Store updates.

Maintainers pin both versions in `scripts/agent-runtime-versions.json`. `make check-agent-updates` queries official stable-release metadata without changing pins or downloading executables. `make stage-store-agents` downloads the selected universal runtimes into a separate directory, verifies official SHA-256 digests, and only promotes the complete set after all payloads and notices succeed. Failed downloads and failed promotion preserve the previous set. Shared/exclusive file locks prevent staging from replacing runtimes while a build reads them. Builds and the artifact evaluator reject receipts with different pinned versions. Codex and its code-mode host always come from the same release.

The direct edition adapts Toone desktop's `CLIAutoUpdateService`, verified downloader and candidate-selection design. Automatic updates are enabled by default, checked once a day with six-hour retry polls, and configurable in Settings → Agents. Background work only updates providers already present on the machine; installing a missing provider requires the corresponding Settings action. The service is disabled in hosted tests and compiled out of Store builds. Its preference and last successful check live in `agents/runtime-updates.json` under AppShow's application home.

Downloaded CLIs live under `agents/runtimes/<provider>/releases/`. Each release is immutable. SHA-256, code signature and exact version verification precede one atomic `current` symlink switch. Codex uses the full official package, including its matching code-mode host, rg, zsh and package manifest. Archive traversal, links and unexpected contents are rejected. Failed or cancelled updates leave the previous pointer intact. Prior version directories are retained for running processes and their resources; no runtime is overwritten in place.

Every new reply resolves the newest working compatible candidate among the managed runtime and user installations. Managed paths resolve to their immutable release directory before launch, preserving the matching helpers during updates. Background discovery never invokes login-shell profiles. The existing explicit readiness path can use the login-shell fallback when no filesystem candidate exists. Provider self-updaters are disabled within AppShow child processes so the application does not indirectly change a user's installation. Terminal sessions retain their normal updater behavior. Manual installer commands remain available as secondary Settings help.

AppShow fetches the official latest stable Codex release and Claude's official latest channel; Claude's delayed stable channel currently predates AppShow's reviewed runtime baseline. `AgentRuntimeCompatibility` centralizes minimum and blocked versions. The source baseline is Codex 0.153.3 / Claude 2.1.263; unrecognized, blocked and older releases cannot be activated. Changing compatibility policy requires review with the provider integration tests.

Every pin change requires provider compatibility checks, both architectures, nested signatures, notices and a new AppShow version/build before release. Rollback of an already shipped Store runtime is another AppShow release containing the earlier pins. Local packaging success does not close signing, licensing, authenticated-provider or App Review acceptance gates.

References: [Apple review guidelines](https://developer.apple.com/app-store/review/guidelines/#software-requirements), [Codex CLI installation and updates](https://developers.openai.com/codex/cli/), [Claude Code update controls](https://code.claude.com/docs/en/setup).
